# 묘한운세 AI 가드레일 구현 계획

작성일: 2026-09-10 / 상태: 구현 진행 중
기준 문서: [AI_GUARDRAIL_POLICY.md](./AI_GUARDRAIL_POLICY.md) v1.1

## 1. 목표와 사용 방법

사주·타로·관상 상담에서 정책을 위반한 답변의 사용자 노출을 줄이고, 검사가 실패한 답변은 반환하지 않는다. 프롬프트만으로 완전한 차단을 보장하지 않는다.

허용·금지 기준은 정책 문서를 따른다. 이 파일에서는 작업 순서, 수정 대상, 검증 결과와 미해결 결정을 관리한다. 정책 변경이 필요하면 정책 문서부터 수정한다. 체크박스는 구현과 해당 검증이 끝난 뒤에만 완료 처리한다.

이 초안 작성은 실제 모델 호출, 운영 데이터 변경 또는 배포 완료를 뜻하지 않는다. 아래 신규 파일명은 제안이며 구현 시 기존 구조를 확인해 조정한다.

## 2. 확정된 내용과 미확정 결정

| 항목 | 현재 상태 | 계획에 미치는 영향 |
|---|---|---|
| 서비스 | 사주·타로·관상 결과 상담, AI는 답변만 생성 | 세 상담 경로에 공통 검사 적용 |
| 생성 모델 | 사용자 제공: `deepseek-v4-flash`, DeepSeek AI API | 기존 API 설정 재사용. 키는 문서·로그에 기록하지 않음 |
| 이용 연령 | **전체 연령 대상 희망·보호자 동의 절차 미구현** | 연령 제한을 임의로 도입하지 않음. 필요한 개인정보 처리 절차는 출시 전 해결 |
| 상담 말투 | 사용자가 정한 예시 없음 | 따뜻한 존댓말, 짧은 설명, 상징과 자기성찰 중심을 초안 기본값으로 사용 |
| 의미 기반 검사 | DeepSeek API로 입력·출력 검사 연결. 정상 상담은 생성 포함 최대 3회 호출 | 실제 모델 비용·시간과 오탐률 측정 후 유지·조정 |
| 비용·성능 | 예산, 이용량, 허용 지연 미확정 | 측정 결과로 임계값 확정. 임의 수치를 승인된 요구사항으로 취급하지 않음 |
| 운영 | 보관 기간, 담당자, 외부 전송 조건 미확정 | 운영 설정과 출시 체크리스트에서 별도 관리 |

추가 모델 호출을 사용하지 않기로 하면 현재 정책의 의미 기반 검사를 어떻게 충족할지 먼저 결정한다. 로컬 검사 모델 또는 검수 템플릿 중심 설계 등을 비교하며, 단순 키워드 검사만으로 정책을 충족했다고 표시하지 않는다. 이 결정과 독립적인 컨텍스트 분리·로그 최소화·공통 정책 작업은 진행 가능하다.

## 3. 수정 대상

| 대상 | 작업 |
|---|---|
| `app/prompts/guardrail.py` (신규 제안) | 정책 버전, 공통 시스템 지침, 입력·출력 검사 지침 |
| `app/services/guardrail.py` (신규 제안) | 판정 스키마, 검사 인터페이스, 위험 우선순위, 승인/차단 흐름 |
| `app/services/guardrail_responses.py` (신규 제안) | 범주별 검수된 고정 응답 |
| `app/services/chat_context.py` (신규 제안) | 서비스별 허용 필드와 안전한 컨텍스트 구성 |
| `app/prompts/face.py`, `saju.py`, `tarot.py` | 공통 정책과 서비스별 페르소나 충돌 해소 |
| `app/routers/chat.py`, `saju_chat.py`, `tarot_chat.py` | 입력·생성·출력 검사 연결, 반환·저장·fallback 통제 |
| `app/config.py` | 검사 제공자, 제한 시간, 길이·토큰 예산, 정책 버전 관련 설정 |
| `app/kafka_logging.py` | 원문 최소화, 판정·지연 중심 이벤트 및 기존 소비자 호환성 확인 |
| `app/schemas.py`, `app/models.py` | 리딩 기반 요청·검사 상태 저장에 필요한 변경 여부 검토 |
| `app/tests/` | 공통 검사 및 세 라우터 통합 테스트 |
| 프런트엔드 상담 호출부·렌더링 | 구현 전 위치 확인. 요청 계약 변경과 텍스트 렌더링 반영 |
| DB 초기 해석 데이터·이력·캐시 | 실제 경로 확인 후 금지 해석 검수와 재노출 통제 |

기존 사주·관상 요청은 자유문장 context와 클라이언트 이력을 받으므로, 서버 리딩 기반으로 바꾸면 프런트엔드와 요청 스키마를 함께 수정해야 한다. 기존 요청을 무검사로 허용하는 호환 경로를 남기지 않는다.

## 4. 단계별 작업

### 단계 A — 실제 데이터 흐름과 API 계약 확인

- [x] 세 상담의 요청 → 모델 → 반환 → DB → 로그 흐름을 기록한다.
- [x] 사주·관상 결과 ID 전달 여부, 회원·게스트 소유권 확인, 서버 대화 이력 저장 구조를 확인한다.
- [x] 프런트엔드 호출부, 기존 테스트 실행 방법, 캐시·로그 소비자 위치를 확인한다.
- [x] 신규 요청 계약과 이력 저장 변경을 정한다. `16_ai_guardrail.sql`에 비파괴 마이그레이션을 작성했다.
- [x] 모델로 전송할 필드를 서비스별로 확정하고, 관상 사진은 브라우저에서만 처리되는 실제 경로를 확인했다.

완료 기준: 세 서비스별 데이터 흐름, 수정 파일, 요청 계약과 마이그레이션 필요 여부가 기록되어 있다.

### 단계 B — 공통 정책과 판정 계약

- [x] 정책 G01~G11을 공통 지침과 검사 기준에 연결한다.
- [x] 입력 판정 `allow / restrict / crisis / out_of_scope`, 출력 판정 `allow / block`을 엄격한 스키마로 정의한다.
- [x] 알려진 규칙 ID만 허용하고 추가 필드·잘못된 타입·모순된 판정을 오류 처리한다.
- [x] 자해, 학대·피해, 타인 위해, 금지 요청, 범위 밖, 검사 장애의 고정 문구를 구분한다.
- [x] 위기 → 금지 → 범위 밖 → 일반 상담 순서를 구현한다.
- [x] 관상 추론 금지, 건강·투자 판단 제한, 안전 교육 허용이 페르소나와 충돌하지 않게 한다.

완료 기준: 모델 없이도 판정·대체 응답 분기를 검증할 수 있다. 생성 모델의 자체 allow 값을 승인 근거로 사용하지 않는다.

### 단계 C — 컨텍스트와 개인정보 최소화

- [x] 서버에서 소유권을 확인한 리딩으로 상담 컨텍스트를 만든다.
- [x] 사주는 필요한 계산 결과, 관상은 검수된 형태 설명, 타로는 카드·자리·방향과 필요한 질문만 허용한다.
- [x] 이름, 원본 생년월일·시각, 사진·랜드마크, 계정·게스트 식별자 등 불필요한 항목을 모델 전달에서 제외한다.
- [x] 질문·이력의 개인정보를 검사하고 명백한 식별자를 마스킹한다. 마스킹을 익명화로 간주하지 않는다.
- [x] 고정 정책만 system 메시지에 두고, DB 문구와 사용자 자료는 별도 user 데이터로 전달한다.
- [x] 검증된 서버 이력을 사용하고, 위조 assistant 메시지·다른 사용자의 리딩을 거부한다.
- [x] 길이·토큰 제한과 이력 축소 규칙을 공통 설정으로 적용한다.

완료 기준: 조작된 context가 시스템 지침으로 승격되지 않고, 금지 필드와 다른 사용자의 결과가 모델 요청에 포함되지 않는다.

### 단계 D — 검사와 생성 흐름 연결

처리 순서: 소유권·형식 확인 → 입력 정제·검사 → 안전 컨텍스트 구성 → 생성 → 전체 출력 검사 → 승인 결과 반환·저장.

- [x] 공통 AI 전송 모듈과 분리된 검사 인터페이스를 구현하고 모의 검사기로 분기를 테스트한다.
- [x] DeepSeek 입력·출력 검사기를 연결하고 생성 요청과 검사 요청의 지침·판정을 분리한다.
- [x] 입력에서 제한·위기로 판정되면 일반 상담 생성을 건너뛰고 검수된 문구를 선택한다.
- [x] 출력에서 정책 위반·개인정보 노출·근거 없는 결과 창작을 검사한다.
- [x] 비스트리밍을 유지하고 전체 승인 전에는 응답 내용을 노출하지 않는다.
- [x] 입력 검사 장애는 생성 중단, 출력 검사 장애는 생성물 폐기로 처리한다.
- [x] 빈 응답, 잘린 응답, 잘못된 JSON, 제한 시간 초과, 호출 실패에서 고정 문구를 사용한다.
- [x] 이미 확인된 위기에는 위기 문구를 유지한다. 확인되지 않은 위험을 확인했다고 주장하지 않는다.
- [x] 자동 재생성은 사용하지 않으며 전체 요청 시간은 공통 설정으로 제한한다.

완료 기준: 세 상담 경로에서 검사 실패 또는 미승인 생성물이 반환·저장되지 않는다. 검사기를 끄면 무검사 생성 대신 고정 응답 또는 기능 중단으로 동작한다.

### 단계 E — 대체 답변·이력·로그·화면 통제

- [x] 타로의 질문 원문 삽입형 `_rule_answer`를 제거하고 검수된 고정 답변을 사용한다.
- [x] 타로 `messages`를 포함한 과거 assistant 답변에서 현재 정책 버전으로 검증되지 않은 항목을 제외한다.
- [x] 현재 AI 답변 캐시가 없음을 확인했다. 이후 캐시 도입 시 정책 버전을 키에 포함한다.
- [x] 승인 답변과 검수된 고정 문구만 사용자용 AI 이력에 저장한다.
- [x] 입력 검사 전 타로 질문 저장 흐름을 수정해 차단 질문 원문을 저장하지 않는다.
- [x] 로그는 원문 없이 정책 버전, 서비스, 규칙 ID, 판정, 위험도와 호출 단계를 기록한다.
- [ ] Kafka·APM·예외 로그·백업에서 원문 또는 비밀이 우회 기록되는지 확인한다.
- [x] 화면이 React 텍스트 노드로 답변을 렌더링하며 모델 HTML을 실행하지 않는 것을 확인했다.
- [x] 검사 장애 문구와 정상 답변에서 내부 프롬프트·키·검사 상세를 노출하지 않는다.

완료 기준: 정상 응답 외에도 장애·이력·로그·화면 경로에서 차단된 생성물이 노출되지 않는다.

- [ ] 기존 DB 해석의 건강·관상·재물 관련 문구를 검수한다.
- [ ] 성능·비용 기준과 정책 담당자를 확정한다.
- [ ] 배포 전 테스트 결과와 미해결 항목을 검토한다.
- [ ] 장애 시 AI 생성을 중단하고 고정 문구를 반환하는 운영 절차를 준비한다. 롤백이 무검사 응답을 다시 활성화하지 않게 한다.

완료 기준: 정책 문서의 P0 항목과 운영 요건 충족. 별도 출시 판단 전에는 완료를 배포 승인으로 간주하지 않는다.

## 5. 권장 진행 순서와 완료 기록

A → B → C → D → E → F → G 순서로 진행한다. 운영 결정은 초기에 확인하되, 결정에 의존하지 않는 설계·모의 테스트·정보 최소화 작업을 먼저 진행할 수 있다. 실제 검사 방식이 미정이면 D의 실제 연동과 F의 실제 모델 평가를 완료 처리하지 않는다.

| 단계 | 상태 | 검증 결과·변경 파일·남은 문제 |
|---|---|---|
| A 데이터 흐름·계약 | 완료 | 서버 리딩 ID 기반 요청으로 변경, DB 마이그레이션 추가 |
| B 공통 정책·판정 | 완료 | 엄격한 판정 스키마·고정 응답·서버 계산 위험도 구현 |
| C 컨텍스트·개인정보 | 완료 | 서버 소유권 확인, 허용 필드 직렬화, 식별자 제외 |
| D 검사·생성 연동 | 구현 완료·실모델 평가 대기 | DeepSeek 입력 검사 → 생성 → 출력 검사, 전체 25초 제한 |
| E 이력·대체·로그·화면 | 구현 완료·운영 점검 대기 | 정책 버전 이력, 원문 없는 판정 로그, React 텍스트 렌더링 |
| F 테스트·평가 | 자동 테스트 완료·실모델 평가 대기 | Python 74개, 프런트 8개 통과. 로컬 API 키 미설정으로 실모델·비용·성능 평가 대기 |
| G 출시 준비 | 미착수 | 보호자 동의·보관·외부 전송 등 운영 결정 필요 |
